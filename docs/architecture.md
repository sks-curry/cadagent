# 架构与工作原理

## 系统分工

大模型负责理解需求、提取结构与参数、选择工具，并根据返回结果安排下一步。Python 智能体负责管理任务、校验和执行工具、保存进度。SolidCraft 负责实际几何计算。

~~~mermaid
flowchart TD
    U[文字与参考图] --> UI[本机网页 / CLI]
    UI --> A[CadAgent 串行工作协程]
    A <--> M[模型 API]
    A --> B[结构参数与补参]
    B --> V[工具 schema / 命令 / 路径校验]
    V --> R[标准件配方 / 原生工具]
    R --> C[MCP / SolidCraft]
    C --> A
    A --> O[测量 / 原生设计 / 导出 / 视图]
~~~

## 一次任务

1. 网页提交文字和图片；后端验证图片并保存规范化像素。
2. 智能体读取 CAD 状态，将需求、必要的参考图、已有参数和工具定义送入模型。
3. 模型先调用 record_design_brief，记录结构、尺寸、来源、假设和缺失项。
4. 缺少关键参数时任务进入 awaiting_parameters，等待用户直接补充。
5. 参数齐全后执行工具。原生命令需先查询真实参数；标准件优先使用已有配方。
6. 工具结果或错误返回模型，继续下一步。几何变化后按配置阶段保存。
7. 结束时测量、保存、导出，并生成等轴测、前/俯/右视图及可打印说明。

这个过程是“观察—规划—执行—反馈”的循环。项目没有训练新的 CAD 模型，也不向模型开放任意脚本执行。

## 工具与几何

模型看到的工具定义来自 MCP schema 和本地配方。应用逐项校验输入，限定命令范围和文件目标。batch 的命令数量有界并请求失败回滚；多个普通工具调用并不构成同一事务。

标准件配方返回参数化 CAD 命令和规格。长方体、开口盒使用命名参数与表达式；齿轮二维齿形由 Python 计算并离散，改变齿数/模数需重新生成轮廓。复杂工程和制造精度仍需额外验证。

## 图片与参数来源

vision.py 验证 PNG/JPEG/WebP，修正方向、缩小过大图片并去除元数据。图像以 user 内容块送入兼容的多模态模型。

| 来源 | 解释 |
| --- | --- |
| user_text | 用户明确描述或确认 |
| image_annotation | 图片中可读的标注 |
| standard | 已选标准/规格确定的值，须记录依据 |
| derived | 基于已知参数的公式推导，须记录依据 |
| inferred | 从外观或比例推测，关键值需要确认 |
| default | 默认假设，关键值不能直接视为已确认 |
| cad_measurement | 实际 CAD 测量 |
| unknown | 仍未知 |

来源标记和推导依据提高可审阅性，不等于自动证明外部标准或公式正确。更严格的规格库与数值验证仍是扩展方向。

普通 screenshot 供用户查看；review_model_view 将真实 CAD 视图送回模型检查可见外形。精确尺寸以测量及独立几何检查为依据。

## 中断与恢复

- 工具 JSON 不完整或响应被截断时，本轮所有工具均不执行。
- 连续输出不完整时保存继续标记，等待继续。
- 模型驱动 CAD 超时后，执行状态可能不确定，不自动重复命令。
- 大型工具返回结果以结构预览和按字段分页传递；几何修改后旧引用失效。
- 任务目标、参考图和设计参数可恢复；完整模型会话仍主要在内存中。

单实例只运行一个任务。多实例的桌面设计互斥、数据库持久化和多用户隔离需要另外实现。

## 核心模块

| 模块 | 职责 |
| --- | --- |
| agent.py | 模型循环、MCP 会话、任务队列和保存 |
| app.py | 本机 HTTP 接口及静态资源 |
| cli.py / configuration.py | 终端、Python 嵌入与多模型配置 |
| recipes.py | 参数化零件配方 |
| design_brief.py / vision.py | 参数校验与图片输入 |
| desktop.py / credentials.py | 本机 CAD 窗口与加密连接 |
| model_limits.py | 工具结果分页 |
| drawings.py / verify_geometry.py | 视图说明与独立几何验收 |
